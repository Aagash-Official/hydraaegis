What we built

Hydra Aegis combines two detection tools into a single workflow. The first tool analyses files to classify malware and flag suspicious behaviour, including threats that don't match any known signature. The second tool watches network traffic to spot command-and-control activity, using anomaly detection to catch techniques that try to blend in with normal traffic.

Detection layers
Layer 1

PE Category Classifier

XGBoost (200 trees) trained on 42 features — 27 static PE header features and 15 dynamic behavioral features. Classifies into Benign, Ransomware, RAT, Stealer, or Trojan.

Layer 2

Family Classifier

Identifies the specific malware family — LockBit, NanoCore, Emotet, and 23 others — once a category is established. 94.3% accuracy across 26 families.

Layer 3

Fileless / PowerShell Detector

Separate Random Forest trained on 26 text features from raw PowerShell script content — no execution required. Catches obfuscation, memory injection, persistence, and C2 download patterns.

Layer 4

Real .exe Scanning + Entropy + UPX

Upload any .exe, .dll, or .zip. Shannon entropy per PE section detects packing. UPX section name fingerprinting gives definitive packing confirmation independent of the ML classifier.

Layer 5

Adversarial Mimicry Attack

A white-box mimicry attack simulating a real attacker who manipulates packing ratio features. Both XGBoost and RF are hardened via adversarial retraining to near-zero evasion.

Layer 6

SHAP Explainability

Model-aware SHAP: TreeExplainer for XGBoost/RF, LinearExplainer for LR/SVM. Every prediction shows a waterfall chart of the top-10 features driving the verdict.

Layer 7

Gemini AI Analyst Reports

Gemini 2.5 Flash generates a four-section report — Threat Assessment, Key Indicators, Investigate Next, Risk Level — from SHAP values and prediction confidence.

Layer 8

VirusTotal Integration

Hash-based lookup — no file upload to VT. Retrieves the threat label and engine count, then estimates behavioral features from the threat category to improve classifier accuracy.

Detection mechanisms
Stage 1

Flow Classifier

Random Forest over 20 per-flow features scores every flow for botnet likelihood. 94.3% recall, cross-validated over 9.5M flows.

Stage 2

Host Verdict

Aggregates flow scores into per-host features and flags compromised hosts. Strong evidence isolates, borderline surfaces for review, a real detection is never dismissed.

Stage 2.5

Peer-to-Peer Botnet Detection

Finds internal hosts acting as P2P botnet nodes by detecting external peers converging on a shared internal socket. Infers the internal network from the capture — works on any network.

Stage 2.6

Jitter-Resistant Beacon Detector

Catches C2 that deliberately jitters its timing to evade detection — what Cobalt Strike is built to do. Timing-regression method validated on real Trickbot (41-day C2, R²=0.9993). Port- and payload-agnostic.

Session

Packet-Level Session Beaconing

Recovers C2 hiding inside a single persistent connection — structurally invisible to flow-level detectors. Reads raw intra-connection packet timing. Cobalt Strike TLS: 362 check-ins, R²=0.9986.

Corroboration

Cross-Mechanism Agreement

No single mechanism is reliable, but agreement across independent mechanisms is high-confidence. A host flagged by several mechanisms is surfaced as corroborated and escalated accordingly.

Explain

SHAP + MITRE ATT&CK

Every detection is mapped to the MITRE ATT&CK technique its evidence genuinely supports. SHAP explains the ML verdict, shown only when the model actually decides.

Respond

Incident-Response Plans

Each suspect gets a Gemini-written containment narrative plus deployable firewall and Suricata/Snort rules. The analyst decides — manual override regenerates the rules, nothing runs automatically.

Cross-mechanism corroboration — the precision multiplier

A host individually weak on every mechanism can still be identified with high confidence when independent mechanisms agree. On the Cobalt Strike capture, host 192.168.2.77 scored 0.00 on the ML classifier alone — yet flagged by host, beacon, and session mechanisms together, correctly identified and quarantined. Validated on six malware families with zero false positives across 216,523 benign flows.

A benign-only autoencoder that never observes an attack label at any point in its lifecycle. It learns a compressed representation of ordinary traffic and flags any flow it cannot faithfully reconstruct — answering the question the supervised model cannot answer about itself: what is it missing?

Four components
Component 1

Novel C2 Anomaly Detection

0.832 AUC on CTU-13 with zero attack labels. Tested unchanged on 325M IoT-23 flows (different network, device class, capture tool, 7 years later) — 0.8268 AUC on like-for-like task.

Component 2

Evasion Robustness

Under padding/high evasion: supervised RF collapses to F1 0.349. Autoencoder rises to 0.859. The attack that defeats the supervised model is the attack the unsupervised model handles best.

Component 3

DNS Tunnel Detection

96.77% overall recall, 72.7% ±15% on A-record tunnels (the honest figure — no record-type shortcut). AUC 0.9956 ±0.0019 across 10 seeds. Pure Python — no Zeek dependency.

Component 4

Host-Level Complementarity

Supervised alone: 9/10 dense infected hosts. Union (supervised ∪ unsupervised): 10/10. Additional review cost: 330 hosts, 1.24% of 26,641. One false positive — stated, not rounded away.

The inverse robustness finding

Under the most severe padding attack the supervised RF's F1 collapses to 0.349. Under the same attack the autoencoder's flag rate rises to 0.859. The mechanism explains the sign: the supervised model learned botnet flows are small, so padding moves them out of the learned region. The autoencoder learned what benign looks like, so padding moves those flows further from the benign manifold.
